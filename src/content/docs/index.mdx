## Three named parts

<CardGrid>
  <Card title="XTXP: the protocol" icon="document">
    The specification every node obeys. **The Math** defines how concurrent edits merge. **The Wire** defines how they travel.
  </Card>
  <Card title="Xmesh: the engine" icon="setting">
    The CRDT engine that resolves concurrent edits on an XML tree. A thin, pure layer on Yrs, the Rust port of Yjs, that adds cycle-safe tree moves. No I/O, no clocks, no threads: everything else is an adapter around it.
  </Card>
  <Card title="MUPPET: the executor" icon="pencil">
    Multi User Progressive Patch Execution Tree. Client-side Xmesh, embedded in Inkscape, in the browser via Wasm, or on a server for no-JS users. It owns every view: the canvas, spatial chat and comments, onion skin and redline. Any MUPPET can host sessions: admitting edits against their grants, routing them and storing them. On a server it runs headless.
  </Card>
</CardGrid>
