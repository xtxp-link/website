The gateway can act as a collaborative overlay for **any existing website**, a kind of "git for the web". Visiting

```
https://xtxp.link/en.wikipedia.org/wiki/Browser@live
```

There is no special proxy address. A website is addressed like any other document, and the [`@{ref}`](/spec/addressing/#one-address-form) says which version: `@live` is the origin as it is now, and any other ref is a branch.

The first visit fetches the canonical page and makes it the genesis state (vector 0). Links and form actions are rewritten to stay inside the gateway, each carrying a ref. Edits POSTed by users become XTXP operations on a branch, and the origin site is never touched.

## The origin site is a peer

Origin pages keep changing after the genesis fetch. XTXP treats the origin as an **upstream peer**: the differences between successive fetches become that peer's operations. Its branch is `@live`. Other branches take in upstream changes the same way they merge anyone else's edits.

## HTML is not XML

Genesis needs an **HTML5 parser** that produces a tree the CRDT can hold. It also needs **node IDs that stay stable when the page is fetched again**. Without them, every re-fetch looks like the whole page was deleted and re-inserted, and every overlay edit gets orphaned.

## Safety requirements

<Aside type="danger" title="An open rewriting proxy is a phishing kit by default">
Without safeguards, anyone could edit a bank's login page and serve it from xtxp.link. Browsers' safe-browsing lists would flag the domain quickly, which would break the whole gateway, including the parts that have nothing to do with overlays.
</Aside>

These are requirements from the first deploy, not later polish:

1. **No credentials pass through.** Never forward cookies, auth headers or form submissions to origin sites.
2. **Origin forms are disabled** in overlays. Only XTXP edit forms submit.
3. **A persistent, visible frame** marks every branch page as an edited copy and links to `@live` and to the original. The ref in the URL does the same job before anyone clicks: `@live` means unedited, anything else means a branch.
4. **Bare links default to `@live`**, so following a plain link never lands someone on an edited branch by surprise.
5. **Origins can opt out**, through robots rules or a response header, and the gateway honours it.
6. **Takedown handling** with a published contact and process.
7. **Sensitive categories** (login, payment and account pages) are read-only or excluded.

Prior art worth studying: Hypothesis's `via` proxy, which overlays annotations on any page, and the Genius Web Annotator, which drew sustained criticism from site owners for overlaying content on their pages without consent. See [prior art](/discussion/prior-art/).
