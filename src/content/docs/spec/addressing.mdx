## `xtxp://` — the native scheme

```
xtxp://{host}/{path}@{ref}
```

Used by native desktop clients, terminal interfaces and automated nodes exchanging XTXP streams. Whether it names the [WebSocket binding](/spec/wire/#bindings) directly or resolves to it through a [muppet disco](/spec/disco/) is [still open](/discussion/open-questions/).

## `https://` — served by the hosting MUPPET

```
https://{host}/{path}@{ref}
```

A MUPPET that hosts a session serves it to ordinary browsers itself, through its server-side MUPPET. This is all the MVP needs.

## `https://xtxp.link/` — a muppet disco

```
https://xtxp.link/{host}/{path}@{ref}
```

<span class="status status--sketch">sketch</span> · a future milestone

xtxp.link doesn't host or serve documents. It is a [muppet disco](/spec/disco/): it finds the MUPPETs hosting the sessions behind an address, and only those the asking key may see, then hands the client on to them. Anyone can run a disco; xtxp.link is one.

## One address form

`{host}` can be a MUPPET hosting native documents, or an **ordinary website**. There is no separate proxy mode. A website is simply a document whose [upstream peer](/spec/web-overlay/#the-origin-site-is-a-peer) is the origin site, and everything else about it is branching.

The `@{ref}` suffix says which version you mean:

| Ref | Meaning |
| --- | --- |
| `@origin` | The website's authoritative version, as served by its origin server: the upstream peer's session. Websites only, read-only. |
| `@main` | The shared collaborative session. The default for native documents. |
| `@{session}` | A named session on this host: a proposed edit, an undo fork, someone's overlay. A session on another host is addressed through that host: `xtxp.link/{other-host}/{path}@{session}`. |
| `@{snapshot}` | An exact point in history: a short hash of a [snapshot](/spec/math/#snapshots-name-points-in-history). *Syntax open.* |

Examples:

```
xtxp.link/en.wikipedia.org/wiki/Browser@origin      Wikipedia's page, unedited
xtxp.link/en.wikipedia.org/wiki/Browser@notes     an edited session of it
xtxp.link/my-laptop.lan/drawing@sketch            a fork, living on a laptop
xtxp.link/xtxp.example.org/drawing@main           a native document
xtxp.link/medium.com/@campey/post@origin            "@campey" stays in the path
```

**Prior art:** the `@` reads like npm's `package@version`, and `origin` follows both git's authoritative remote and HTTP's *origin server* ([prior art](/discussion/prior-art/#addressing-and-branching)).

## Parsing rules

1. **The last `@` starts the ref.** Every other `@` belongs to the path, so origin paths like Medium's `/@user` need no escaping.
2. **Generated links always carry a ref.** That includes every link it rewrites inside a page, so the last `@` is never ambiguous.
3. **Bare URLs** (typed or pasted from elsewhere):
   - with no `@` at all, redirect to the default ref (`@origin` for websites, `@main` for native documents)
   - with an `@` whose text doesn't resolve to a ref, as in `medium.com/@campey`, treat it as part of the path and redirect to `…/@campey@origin`
4. **A first path segment without a dot is a keyword**, reserved for the disco's own pages (such as `/d/` for diagrams). Hostnames always contain a dot, so the two never collide.

## The ref is the honesty signal

`@origin` means unedited. Any other ref means a session that may contain other people's edits, and the page frame says so, with links to `@origin` and to the original site. The ref travels with every shared link, so a reader can tell what they're looking at before they click. That supports the [overlay safety requirements](/spec/web-overlay/#safety-requirements).

## Content negotiation

| Request | Response |
| --- | --- |
| WebSocket upgrade | The live XTXP stream of Yrs updates, for MUPPETs and automated nodes ([The Wire](/spec/wire/#one-wire-format-to-start)). |
| `Accept: text/html` | The current state rendered as HTML, with forms that POST edits. Served by the host's server-side MUPPET. |
| A person who wants their native client | A plain link to `xtxp://{host}/{path}@{ref}`. |

<Aside type="caution" title="Native hand-off">
The first sketch used `<meta http-equiv="refresh">` to bounce browsers to `xtxp://`. A server can't tell whether a protocol handler is installed, and a refresh to a missing handler fails silently. A visible link always works, and it needs no JavaScript.
</Aside>

## Deep links and short links

- **Snapshots**: `@{snapshot}` names a document at an exact point in history, so a historical state can be shared exactly. How the snapshot hash is written in a URL is <span class="status status--open">open</span>.
- **Discovery**: a [muppet disco](/spec/disco/) resolves an address to the MUPPET currently hosting the session.
- **Short links**: short, low-density URLs that make easily scanned QR codes, for bridging paper and screens.
